# Release Briefing

## First-Run Interview

Before the first package, ask:

- Where Eric publishes: newsletter, blog, internal doc, social post, or other surface.
- Audience sophistication level.
- Title, subtitle, length, and format conventions.

If a `my-voice` skill is available and calibrated, use it for the final prose.

## Freshness Rule

This skill packages research. If research is missing, stale, or unsourced, stop and run current-info search first. Every factual claim must carry a date and source. Label unverified claims as unverified.

## Package Structure

Use this exact structure:

```markdown
# Title

Subtitle

## What Actually Changed
- Fact, date, source:

## Why It Matters For This Audience
- ...

## What To Do About It
- Immediate:
- This week:
- Watch next:

## Caveats And Unknowns
- ...

## Thumbnail Prompts
### Option 1
- Prompt:
- Brand/color notes:

### Option 2
- Prompt:
- Brand/color notes:

### Option 3
- Prompt:
- Brand/color notes:

## Sources
- Date - Source - URL/path
```

Use 2-3 thumbnail prompts. Match the subject's brand colors when known. Do not invent brand colors; if unknown, say so and use visual cues from sourced product materials.

## Claim Discipline

- Include concrete dates for release, announcement, observed change, and source access.
- Separate confirmed facts from interpretation.
- Do not turn rumors into facts.
- When vendor wording is vague, quote sparingly and explain uncertainty.

## Output Standard

Make the briefing publish-ready for the configured surface, but keep source notes traceable. If the release has no meaningful action for the audience, say so.
